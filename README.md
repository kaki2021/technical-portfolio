## 1. Runtool：从自动化脚本到统一测试平台

这是我在软件工具测试工作中主导开发的内部工具。公开作品集不提供公司源码、客户信息、真实路径、内部模板或业务数据，只整理本人负责部分的工程思路和平台演化过程。

项目最初只是为快速交付单个需求编写的特异性脚本。随着需求增加，逐步出现重复逻辑、脚本分散、维护困难、批量测试成本高和人工汇总工作量大的问题，因此继续演化为统一入口和模块化的平台结构。

后期覆盖的实际能力包括：

- 批量测试任务；
- 参数动态配置；
- 测试报告自动生成；
- 结果对比；
- 性能数据统计；
- 日报 / 周报等信息汇总；
- 团队使用支持与问题排查。

项目由驻场团队 10+ 名成员使用，并减少了相当一部分依赖人工整理的项目进度汇总工作。

**详细复盘：** [Runtool：从自动化脚本到统一测试平台](docs/runtool-case-study.md)

## 2. 归山村落运营协作小程序

面向多人共同运营场景设计的一体化微信小程序，覆盖任务、工作记录、库存、采购、领料、财务、报销、成员、权限和 AI 辅助等模块。

项目重点不只是 CRUD，而是处理实际业务中的状态与责任关系，例如：

- 任务从认领到提交、确认、打回的状态流转；
- 采购从申请、审批、购买、核验、入库到记账的完整流程；
- 金库、待报销、采购垫款和长期借款之间的账务边界；
- 主管、库管等角色与业务地点绑定；
- 操作记录和历史留痕；
- 金额、XP、出勤等确定性数据由程序计算，AI 只做辅助整理和表达。

**项目地址：** https://github.com/kaki2021/guishan-village-ops-miniapp

## 3. 观象 · 六爻占问 Android

一款 Android 本地应用，将确定性排盘与规则计算、案例管理和 AI 辅助分析结合起来。

工程上重点处理了：

- Android 原生层与 Python 嵌入；
- Java + Chaquopy + Python + WebView 的混合架构；
- SQLite / JSON 本地数据；
- 规则计算与模型语言分析分离；
- API Key 的本机安全存储；
- 加密规则包导入；
- 多阶段 AI 请求、格式校验、错误修复与历史保留。

公开仓库不包含真实规则资产、个人案例数据库、API 密钥或签名材料。

**项目地址：** https://github.com/kaki2021/liuyao-divination-android

## 5. 共创协作框架

一套从早期共创平台设计和试运行材料中整理出的通用协作框架，重点处理成员自主执行、任务与成果关系、贡献核算、岗位轮换和共同治理。

仓库把组织规则、计算公式、人工智能提示词、机器可读参数和填写模板放在一起。人工智能负责整理事实与提出建议，任务是否成立、成果是否验收以及最终贡献值仍由人确认。

这个项目主要体现我把**组织问题拆成可执行规则，并进一步整理成文档、公式、配置和协作模板**的能力。

**项目地址：** https://github.com/kaki2021/co-creation-framework

## 我更关注的工程问题

不同项目使用的技术不同，但我反复处理的是类似的问题：

```text
真实需求
   ↓
拆解输入 / 状态 / 人工步骤
   ↓
明确确定性逻辑
   ↓
自动化重复流程
   ↓
引入适合的 AI 能力
   ↓
增加校验 / 日志 / 权限 / 重试
   ↓
逐步形成可复用、可维护的系统
```

因此，这个作品集不对应单一岗位名称。它主要展示我在**发现问题、拆解流程、设计工具、集成 AI、开发应用并完成实际交付**方面的项目经验。
